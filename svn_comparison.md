# Git vs SVN: ответы на вопросы

1. **Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?**
   В Git ветка — это просто указатель (лёгкая ссылка) на конкретный коммит, создание занимает миллисекунды и не копирует файлы. В SVN ветка физически реализована как копирование директории на сервере, что требует времени и места на диске, особенно на больших репозиториях.

2. **Можно ли в SVN сделать коммит без интернета? Почему?**
   Нет. SVN — централизованная система: у клиента нет полной истории репозитория, а коммит — это операция записи прямо на центральный сервер. Без соединения с сервером зафиксировать изменения невозможно, доступны только локальные правки файлов.

3. **В каких сценариях SVN до сих пор может быть предпочтительнее Git?**
   В legacy-инфраструктуре (госсектор, банки) с уже отлаженными процессами вокруг SVN, при работе с большими бинарными файлами (где SVN исторически имел плагины вроде enterprise-хранилищ) и там, где нужен жёсткий централизованный контроль доступа к каждой части репозитория на уровне сервера.
